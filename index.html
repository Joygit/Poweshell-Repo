Introduction to PowerShell

PowerShell is a cross-platform task automation shell and scripting language built on .NET. It uses a verb-noun command structure (cmdlets) and passes structured .NET objects through its pipeline.

🔷

Cmdlets

Commands following Verb-Noun pattern. E.g., Get-Process, Set-Item, New-AzResourceGroup.

🔗

Pipeline

Pass .NET objects between cmdlets using |. Unlike bash, you pass rich objects, not plain text strings.

📦

Modules

Packaged collections of cmdlets. Import with Import-Module or auto-loaded from $PSModulePath.

🌐

Cross-Platform

PowerShell 7+ runs on Windows, Linux, and macOS. Perfect for Azure DevOps pipelines and cloud automation.

first-steps.ps1
PowerShell
# Check version $PSVersionTable.PSVersion # Get help for any cmdlet Get-Help Get-Process -Full Get-Help *-Service # Wildcard search # Discover commands Get-Command -Verb "Get" Get-Command -Module "Az.Resources" # Explore object properties Get-Process | Get-Member Get-Process | Select-Object -Property Name, CPU, WorkingSet # Execution policy (run once as Admin) Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser

Azure Automation Runbooks

Runbooks are scripts that run in Azure Automation accounts — perfect for scheduled tasks, event-driven workflows, and cloud management automation.

📋

PowerShell Runbook

Standard runbook type. Runs synchronously, returns output. Best for most automation tasks.

⚡

PowerShell Workflow

Supports checkpoints and parallel execution. Good for long-running, resumable tasks.

🐍

Python Runbook

Python 2/3 support for teams preferring Python or using Python-native libraries.

🔷

Graphical Runbook

Visual drag-and-drop designer for non-developers. Converts to PowerShell under the hood.

✅
Best Practice: Enable System-Assigned Managed Identity on your Automation Account and assign it the least-privilege RBAC roles. Never store credentials as plaintext — use the Automation Credential asset or Key Vault.
runbook-template.ps1
Runbook Template
#################################################################### # Runbook: Start-VMsOnSchedule # Description: Start tagged VMs on a schedule # Author: Platform Engineering # Version: 1.0.0 # Required Modules: Az.Accounts, Az.Compute #################################################################### param ( [Parameter(Mandatory = $false)] [string]$ResourceGroupName = "rg-prod-eastus", [Parameter(Mandatory = $false)] [string]$TagKey = "AutoStart", [Parameter(Mandatory = $false)] [string]$TagValue = "true" ) #region INIT $ErrorActionPreference = "Stop" $VerbosePreference = "Continue" Write-Output "[$(Get-Date -f 'yyyy-MM-dd HH:mm:ss')] Runbook started" # Authenticate via Managed Identity try { Connect-AzAccount -Identity Write-Output "Connected via Managed Identity" } catch { Write-Error "Auth failed: $($_.Exception.Message)" throw } #endregion #region MAIN $vmsToStart = Get-AzVM -ResourceGroupName $ResourceGroupName | Where-Object { $_.Tags.$TagKey -eq $TagValue } Write-Output "Found $($vmsToStart.Count) VMs tagged for auto-start" $jobs = foreach ($vm in $vmsToStart) { Write-Output " → Starting: $($vm.Name)" Start-AzVM -Name $vm.Name -ResourceGroupName $vm.ResourceGroupName -NoWait -AsJob } Write-Output "Waiting for all start operations..." $jobs | Wait-Job | Receive-Job Write-Output "[$(Get-Date -f 'yyyy-MM-dd HH:mm:ss')] All VMs started successfully" #endregion
